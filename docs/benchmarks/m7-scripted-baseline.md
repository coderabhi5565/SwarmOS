## Method

- **Sequential latency only.** Trials run one at a time (concurrency 1), in the stored seeded order; every figure below is a latency of a run executed alone.
- **Warm-up.** The first 1 repetition(s) of each arm and task run first and are excluded from every rate, distribution and timing (reason `warm-up`).
- **Measured n** counts trials that finished with a success or a failure. Cancelled, interrupted and orchestration-error trials are excluded with their reason and are **not rerun**, so a short sample reports its actual n and is marked incomplete.
- **Timings** come only from each run's persisted span measurements. A trial without recorded measurements is counted by status and enters no timing figure; a value a run did not establish is `—` with its reason, never zero.
- **Kinds.** *elapsed* is one interval or the length of a union; *busy* is a sum over possibly overlapping intervals; *total* is time spent, not elapsed; *count* is a number of events.
- **Statistics.** The median is `statistics.median` (the mean of the two middle values for even n). P95 is nearest-rank: the value at 1-based rank ceil(0.95 × n) of the sorted values, always an observed value; for n < 20 it is the maximum.
- **No significance claim.** Twenty measured trials per arm and task do not establish a statistically significant difference. No confidence interval or test is computed, and no arm is declared best.

## Limitations

- One machine and one process; results describe this environment only.
- Host facts beyond the platform string and Python version (CPU count, memory) were not recorded.
- Failures are not broken down by error class: the trial metrics do not record it.
- The scripted provider answers instantly, so model latency is absent and call times are in-process time.
